# binCV expected check counts -- the floor scripts/verify.sh enforces.
#
# WHY THIS FILE EXISTS
#
# CLAUDE.md says "a drop in the CHECKS column is a regression even when every
# ctest case still passes", and TASKS.md T1.7 requires that the test count not
# fall below what it was before the Google Test migration. Until this file
# existed both sentences were enforced by a human remembering four numbers:
# verify.sh printed CHECKS and compared it against nothing. Measured -- deleting
# test_storage from BINCV_CORE_TESTS took core from 1892 checks to 1348 and the
# gate still printed ALL CONFIGURATIONS GREEN and exited 0.
#
# HOW IT IS READ
#
#   <configuration>  <suite>  <checks>  <skipped>       (tab-separated)
#
# verify.sh fails the configuration when a suite reports FEWER checks or FEWER
# skips than its row here, when a listed suite did not run at all, or when a
# suite ran that has no row. A count that RISES is not a failure; it prints a
# notice, because raising the floor should be a reviewed edit rather than a side
# effect of running the gate:
#
#   ./scripts/verify.sh --update-checks-baseline
#
# and commit the diff with the change that earned it.
#
# WHY SKIPS ARE A SEPARATE COLUMN
#
# Without exceptions BINCV_CHECK_THROWS cannot evaluate its expression, so those
# checks are reported as skipped and covered as death tests instead. They are
# still coverage that can be deleted, so they get their own floor: a run where
# noexcept/test_binMat reported 801 checks and 0 skips would otherwise look
# identical to a healthy one.
#
# WHY THE FOUR CONFIGURATIONS DIFFER, LEGITIMATELY
#
#   debug     test_error 21 vs 31 elsewhere. tests/test_error.cpp guards ten
#             checks with `#if !BINCV_DEBUG_CHECKS` -- they assert that
#             BINCV_ASSERT compiles away under NDEBUG, which is not a statement
#             the Debug build can make. Totals: core 1892, debug 1882.
#   noexcept  44 + 16 validation checks move from in-process to death tests, and
#             test_error drops the 17 exception-shaped ones. Total 1815 + 60s.
#   opencv    adds test_opencv_interop and test_equivalence (T2.1, which needs
#             cv::Mat); otherwise identical to core.
#   test_logic  65768 under opencv, 53672 everywhere else. The 12096 difference is
#             the Tier 1 half of T2.2 -- bit-exactness against cv::bitwise_and /
#             _or / _xor / _not over the full T2.1 size and fill matrix -- which
#             only compiles where OpenCV does. The other 53672 are the per-pixel
#             reference, the differing-stride sweep, in-place aliasing, the
#             degenerate shapes, the padding-bit invariant, the dirty-source
#             sweep, the alias-acceptance cases and the trailing-word contract,
#             and they run in all four configurations because the kernels are
#             core code.
#             It was 56044 / 43948 when T2.2 was first written. The 9724 added to
#             each are three review findings turned into cases: sources whose
#             padding was already dirty (without them, deleting the trailing-word
#             mask from applyBinary left the whole suite green), views over one
#             buffer whose rows do not meet (the alias predicate rejected them
#             and aborted Debug builds), and the destination's trailing word at
#             BIT granularity.
#   test_shift  307133 under opencv, 99695 everywhere else. The 207438 difference
#             is the Tier 1 half of T2.3/T2.4: impl::borderIndex against
#             cv::borderInterpolate coordinate by coordinate, and the shifted
#             images against cv::copyMakeBorder over the T2.1 size matrix for all
#             five BorderTypes, plus the three cases that pin cv::erode's and
#             cv::dilate's default border VALUES -- the premise D-12's fill
#             decision rests on.
#             It was 112733 when T2.3/T2.4 were first written, and the 194400
#             added are one review finding turned into cases: that sweep read
#             equivalenceWidths() x {1, 3, 17} at a single fill of 0.5 while the
#             surrounding prose claimed the T2.1 matrix, and its offsets never
#             reached past the HEIGHT at a height above 1 -- the regime T2.4's
#             done-when clause names. Measured: a clamp injected into shift()'s
#             row loop that is wrong only past the height failed 144 checks, all
#             of them in Shift.Borders_*, and left every Shift.OpenCv_* green.
#             The sweep now runs equivalenceHeights() and equivalenceFillRatios()
#             as well, with offsets past each extent and both at once, and that
#             clamp fails 2768 checks including all four Shift.OpenCv_*.
#             The other 99695 are the naive per-pixel
#             reference sweep (k from 0 to 2*WordBits+1 in both directions, at
#             every word width), the vertical sweep past the image height, every
#             BorderType with both fill values in both axes, the degenerate
#             shapes, the differing-stride combinations, sources whose padding
#             bits are already dirty, the guard-word check, the disjoint-views
#             acceptance cases, and the closed-form border mapping against an
#             independently written iterative one. They run in all four
#             configurations because the kernels are core code -- and the Debug
#             one is the only place their BINCV_ASSERT preconditions are live.
#   test_reduce  711812 under opencv, 546572 everywhere else. The 165240
#             difference is the Tier 1 half of T2.5 -- countNonZero against
#             cv::countNonZero over the full T2.1 size and fill matrix, whole
#             image and by region -- plus the Tier 3 masked reductions against an
#             OpenCV composite (cv::bitwise_and into a temporary, then
#             cv::countNonZero), which is a second reference and not a tier
#             promise. The other 546572 are the per-pixel reference sweeps for
#             all three entry points, the exhaustive region GEOMETRY cross
#             product, the padding contract, the differing-stride combinations,
#             the degenerate shapes, the LK covariance identity, and the 16 that
#             keep impl::popcountWordPortable -- the builtin-free popcount that no
#             GCC/clang configuration would otherwise execute one instruction of
#             -- from being untested source. They run in all four configurations
#             because the kernels are core code.
#             This suite counts ONE CHECK PER (case, region) rather than per case:
#             every interesting input here is a region, so a per-case count would
#             leave the CHECKS column blind to a region list that got shorter,
#             which is this suite's most likely regression. Per pixel would be the
#             other extreme and would drown the summary.
#             The floor has teeth, measured by mutating ops/reduce.hpp (checks
#             passed, out of the 546468 core checks the suite had before the
#             portable-popcount case added 16 more):
#               tail mask dropped                496202 -- 6 case families
#               head mask dropped                491251 -- 6 families
#               one-word region drops head mask  488559 -- 6 families
#               tail mask off by one             511817 -- 6 families
#               interior loop revisits lastWord  443742 -- 7 families, Geometry included
#               whenClear = total (split lost)   470980 -- 5 families
#               region not clipped to the width  SEGFAULT after 19 failing cases
#               whole-image count trusts the
#               padding invariant (T2.5's
#               literal reading)                 545919 -- Reduce.DirtyPadding ONLY
#             The last row is the one worth reading: the padding decision in
#             ops/reduce.hpp is invisible to every other case in the suite, and
#             Reduce.DirtyPadding_* is the only thing standing between it and a
#             silent over-count on a wrapped buffer.
#             THE +88 FROM THE T2.5/T2.6 REVIEW (546484 -> 546572) are three
#             things a value sweep could not see, so each was mutation-checked
#             rather than assumed (baseline 711812 under opencv):
#               SplitCount::crossTerm() sign flipped     709356 -- Covariance
#               crossTerm() returns the sum instead      709432 -- Covariance
#               Rect::empty() uses < 0 instead of <= 0   711800 -- 8 families
#               Rect::operator== ignores height          711808 -- 8 families
#               Rect::operator!= loses its negation      711792 -- 8 families
#             The Rect rows are small on purpose: those three members had zero
#             call sites and zero coverage anywhere in the repo, so a wrong body
#             shipped green in all four configurations. Two checks are cheap; a
#             silently wrong region predicate under T3.6 is not. Reduce.Covariance
#             also now compiles the constMagnitude()/constSign() spelling from a
#             deliberately NON-const container, which is a compile-time check that
#             costs one runtime check and pins the advice ops/reduce.hpp gives.
#             The ctest count rose by one too: reduce-empty-extent, a death test
#             for impl::regionFromExtent's non-empty precondition, which no public
#             entry point can reach and which underflows into a ~5.8e17-word row
#             range if it is ever removed.
#   test_equivalence  9923 -> 16403. The added 6480 are the packing anchor's new
#             QuantMat plane row: T2.2's per-plane Tier 1 checks read binCV back
#             through constPlane() -> unpackTo8U, and that conversion was the one
#             the anchor did not pin.
#
# WHY test_equivalence HAS NO FAULT-INJECTED ROWS
#
# tests/CMakeLists.txt also builds test_equivalence four more times with a
# deliberate fault compiled in, each registered WILL_FAIL. verify.sh skips
# WILL_FAIL tests when harvesting, so those runs are counted here neither as
# checks nor as skips -- which is correct: they exist to prove the harness can
# fail, and their check totals are supposed to be lower.
#
# KNOWN GAP, and it is in verify.sh rather than in this file: nothing enforces a
# floor on the number of ctest CASES. Measured -- commenting out the four
# bincv_add_faulted_equivalence_test() calls took the OpenCV configuration from
# 47/47 to 44/44 ctest cases with the CHECKS column unchanged at 5316, and the
# run still printed ALL CONFIGURATIONS GREEN and exited 0. The baseline loop only
# iterates rows present here (the fault targets deliberately have none, so
# MISSING SUITE cannot fire), the UNRECORDED SUITE branch only fires for suites
# that ran, and the CTEST column is compared solely against the literal '-'.
# Closing it properly needs a ctest-case floor in scripts/verify.sh. What is in
# place instead is that test_equivalence now carries the "this harness can fail"
# property IN-PROCESS -- Equivalence.ExpectBitExactReportsFailures drives
# expectBitExact's own failure path through VerdictCapture -- so deleting the
# WILL_FAIL targets no longer deletes the proof, and the in-process version does
# have a floor: the row below.
