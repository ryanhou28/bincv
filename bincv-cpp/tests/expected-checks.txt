# binCV expected check counts -- the floor scripts/verify.sh enforces.
#
# WHY THIS FILE EXISTS
#
# CLAUDE.md says "a drop in the CHECKS column is a regression even when every
# ctest case still passes", and TASKS.md T1.7 requires that the test count not
# fall below what it was before the Google Test migration. Until this file
# existed both sentences were enforced by a human remembering four numbers:
# verify.sh printed CHECKS and compared it against nothing. Measured -- deleting
# test_storage from BINCV_CORE_TESTS took core from 1892 checks to 1348 and the
# gate still printed ALL CONFIGURATIONS GREEN and exited 0.
#
# HOW IT IS READ
#
#   <configuration>  <suite>  <checks>  <skipped>       (tab-separated)
#
# verify.sh fails the configuration when a suite reports FEWER checks or FEWER
# skips than its row here, when a listed suite did not run at all, or when a
# suite ran that has no row. A count that RISES is not a failure; it prints a
# notice, because raising the floor should be a reviewed edit rather than a side
# effect of running the gate:
#
#   ./scripts/verify.sh --update-checks-baseline
#
# and commit the diff with the change that earned it.
#
# WHY SKIPS ARE A SEPARATE COLUMN
#
# Without exceptions BINCV_CHECK_THROWS cannot evaluate its expression, so those
# checks are reported as skipped and covered as death tests instead. They are
# still coverage that can be deleted, so they get their own floor: a run where
# noexcept/test_binMat reported 801 checks and 0 skips would otherwise look
# identical to a healthy one.
#

#             ellipse5x5@(0,4) and cross5x5@(4,1), every one off-centre. A suite of
#             rect and cross at centred anchors would have passed the flip
#             5040/5040 -- measured directly, before this suite existed.

#             THE FALLBACK ROW HAD TO BE EARNED TWICE. The fallback recurrence --
#             the branch morphRowGeneric takes when an element reaches a whole WORD
#             sideways and the three-word window cannot express it -- is the
#             hardest path in the file to discriminate, because everything that
#             reaches it is wide and most wide things are symmetric.
#               * Its offset PERTURBED BY ONE first survived 298381/298381: the
#                 wide elements were solid rects, and sliding a CONTIGUOUS offset
#                 range by one changes only which columns fall outside the image,
#                 and those read the border either way. The sparse wide mask -- two
#                 cells at the extremes of a wide span -- is what sees it.
#               * Its offset SIGN then survived too, 298541/298541, and that was
#                 found in T3.3's review rather than by its author. Both families
#                 reaching the fallback were point-symmetric about their anchor:
#                 the rects were centred, and the sparse mask's cells sat at
#                 {0, half, cols-1} around an anchor at half. Anchoring the wide
#                 rects at column 0 and at column `size - 1` as well makes the
#                 offset set {0..size-1} and {-(size-1)..0}, and the mutation now
#                 fails 42 checks. 42 is small because only the widest elements at
#                 each word width reach that branch at all; it is not zero, which
#                 is the property the row asserts.
#   test_resample  245312 in ALL FOUR, which is the point rather than an
#             omission: horizontal decimation (E-8 / X-14) has no OpenCV
#             counterpart to compare against -- cv::resize resamples both axes on
#             a byte image and rounds rather than keeping the even columns -- so
#             the suite has no Tier 1 half to gain under `opencv` and nothing to
#             lose without exceptions. The number is one check per destination
#             pixel per variant across the width sweep (0 .. 3*WordBits+3 plus the
#             pyramid ladder) at four word widths, times three implementations,
#             plus the padding, stride, degenerate, row-view and plan-size cases.
#             Three implementations because X-14 compares three routes and the
#             protocol requires each to be correct BEFORE any is timed; a
#             two-thirds drop here means a losing arm was deleted, which is
#             exactly what the floor is for.
#   test_pyramid  262008 under opencv, 236122 everywhere else. The 25886
#             difference is the reference pipeline's own BOX_2x2 path (T3.4,
#             X-15): cv::blur(2x2) then PyrDownInvoker's disableGaussian
#             early-out, which is what SEAL/src/keypoint_tracking/pyramids.cpp
#             runs. It is a SECOND REFERENCE and not a tier promise -- pyrDown is
#             Tier 2 (ARCHITECTURE 5.1), so there is no bit-exactness to check --
#             and it carries three separate claims: that cv::blur on CV_8U is
#             ceil(sum/4) rather than the mean rounded to nearest (which is where
#             ARCHITECTURE 7.2's 192 comes from), that binCV is the mean rounded
#             once half up, and that cv::blur's DEFAULT anchor puts its window
#             half a pixel up and to the left. The last is checked OpenCV against
#             OpenCV so that only the anchor differs between the two sides.
#             The other 236122 are one check per destination pixel across the
#             width sweep (0 .. 2*WordBits+3 plus the pyramid ladder) at four
#             heights, for thirteen (NIn, NOut, WordType) instantiations, plus:
#             the requantizer's ENTIRE input space enumerated per (NIn, NOut) --
#             every sum from 0 to 4*(2^NIn - 1), packed into the lanes of the
#             words under test so lane independence comes out of the same
#             enumeration; the four bit-sliced primitives underneath it
#             (addPlanes, multiplyByAllOnes, addConstant, divideByConstant,
#             quotient AND remainder); agreement with THE FORMULATION T3.4
#             REJECTED, both at the word level (boxSum4 vs boxSum4Replicated) and
#             for the whole kernel (pyrDown vs impl::pyrDownReplicated); the
#             edge-replication rule checked a second way, against a source whose
#             last column and row were duplicated by hand; dirty-source padding;
#             differing strides; degenerate shapes; and the four-level ladder.
#             THE ROUTE-AGREEMENT CASES ARE THE ONES TO PROTECT. impl::
#             boxSum4Replicated is the exponential k = 4*(2^NIn - 1) route T3.4
#             replaced, kept under test precisely so the replacement is a
#             comparison rather than a claim -- the same argument test_resample
#             makes for E-8's losing arms. Deleting it would take ~15000 checks

#             The floor has teeth, measured by mutating ops/pyramid.hpp (checks
