# binCV CUDA backend expected check counts -- the floor scripts/verify_cuda.sh enforces.
#
# The CUDA suites' twin of tests/expected-checks.txt, and the same contract:
#
#   <configuration>  <suite>  <checks>  <skipped>       (tab-separated)
#
# verify_cuda.sh fails when a suite reports FEWER checks or skips than its row,
# when a listed suite did not run, or when a suite ran that has no row. A count
# that RISES prints a notice; raising the floor is a reviewed edit:
#
#   ./scripts/verify_cuda.sh --update-checks-baseline
#
# and commit the diff with the change that earned it.
#
# WHY THIS IS A SEPARATE FILE. verify.sh builds no .cu translation unit, so it can
# never produce these rows -- and its --update-checks-baseline rewrites every row
# of its own file from the configurations it ran, which would delete them.
#
# WHY RELEASE AND DEBUG DIFFER, LEGITIMATELY. A device op that accepts a narrower
# domain than its host twin asserts the domain and then returns an error. A test
# that calls it with a deliberate violation can only compare the error code where
# the assertion is compiled out, so in Debug each such call site is reported as
# "[not run in a checked build]" and counts one fewer check
# (BINCV_CHECK_EQ_UNLESS_CHECKED in tests/test_util.hpp). A refusal with no
# assertion on its path is an ordinary check and runs in both. The per-suite
# difference is therefore exactly the number of those lines the suite prints.
